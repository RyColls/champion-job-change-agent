Follow one job change through the agent

When someone who champions a product changes jobs, two things are at stake: the old account may lose its champion without anyone noticing, and the person may be a warm lead at a new company. This agent reads each job-change event, runs it through seven checks, and queues work for a person. It never sends anything.

Cairnboard, its customers and every person in this walkthrough are fictional, and the job-change feed is simulated. Each event below is a real row from this project's simulated feed, run through the real code.

What this does not show

  • It has not touched a real company, a real person or a data provider. The feed is simulated and the numbers describe this project's test data only.
  • It has not prevented any churn or generated any pipeline, and nothing here is deployed.
  • The model answers on this page were recorded and replayed. The live API backend is unit-tested against a fake client but was not run against the real API in this build.
  • When the feed gives no prior employer, a real move and a look-alike stranger look identical to the agent. It holds those for a person instead of guessing. A provider-supplied profile ID would fix this.
  • The offline reader only understands the announcement formats the simulator writes. The recorded Haiku answers matched it on every post in this feed, which shows these were handled, not that arbitrary text is solved.

Run it yourself

Python 3.11 or newer. No API key is needed for the deterministic and recorded backends.

pip install -r requirements-dev.txt
python -m pytest                                        # 46 unit tests
python -m agent.cli --feed eval2 --backend recorded     # run the pipeline
python -m evals.run_acceptance --feed eval2 --backend recorded
python demo/walkthrough.py                              # rebuild this page
